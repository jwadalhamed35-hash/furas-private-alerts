# مراقب فرص — محطات الوقود والفنادق

مشروع Python يعمل سحابياً عبر GitHub Actions كل ساعة، دون تشغيل جهازك ودون اشتراك ذكاء اصطناعي. لا يحتاج إلى حساب في منصة فرص لقراءة البيانات العامة. لا ينشئ حسابات أو مجموعات ولا يفعّل نفسه قبل رفعه وإعداد قناة الإرسال.

## القرار العملي قبل البدء

- **الخيار المجاني الأبسط:** مستودع GitHub عام + بوت تيليجرام في مجموعة أو قناة. على المشغلات القياسية، دقائق Actions للمستودعات العامة مجانية. يستطيع البوت إرسال هذه التنبيهات دون خدمة مدفوعة ضمن حدود Telegram العادية.
- **واتساب الرسمي:** الكود يدعم Groups API، لكن إنشاء رقم عادي وإضافته لمجموعة موجودة ليس إعداداً كافياً. بحسب توثيق Meta الذي روجع في 20 نوفمبر 2026، يلزم Official Business Account (OBA)، والمجموعات لها حد 8 مشاركين، وأرقام تطبيق WhatsApp Business غير مؤهلة لهذه الواجهة. تستخدم الخدمة تسعيراً للرسائل؛ لا أعدك بتشغيلها مجاناً. أنشئ مجموعة عبر واجهة Meta المؤهلة وادعُ المشاركين إليها وفق دليلها.
- لم يُستخدم WhatsApp Web غير الرسمي؛ فهو يضيف اعتماداً على جلسات وربط هاتف واستضافة مستمرة، ولا يحقق ضمان مجانية واستقرار بلا صيانة.
- الفحص كل ساعة يعني الاكتشاف في الدورة التالية؛ قد تتأخر جدولة GitHub أو تسقط بعض الدورات عند الضغط. لا يوجد ضمان خدمة 24/7 أو إشعار لحظي.
- قد يعطّل GitHub الجدولة في المستودعات العامة بعد 60 يوماً دون نشاط. راجع Actions دورياً وأعد التفعيل عند الحاجة. لا تعتمد على وصول فرص جديدة لتضمن بقاء الجدولة مفعلة.
- المستودع الخاص على GitHub Free له 2000 دقيقة شهرياً مشتركة مع مهامك الأخرى. 720–744 فحصاً شهرياً قد تستنفدها حسب المدة؛ لا تفترض المجانية فيه. لا تفعّل إنفاقاً مدفوعاً إن كان شرطك صفراً من التكلفة.

## ماذا يفعل البرنامج؟

1. يقرأ إعداد خريطة الفرص من المصدر العام المرتبط بصفحة «الفرص الاستثمارية» الرسمية، ثم يستعلم عبر وسيط الخريطة الرسمي عن طبقة الاستثمار.
2. يجمع معرفات السجلات أولاً ثم يقرأها بدفعات من 100. يفشل عند وجود دفعة ناقصة بدلاً من اعتبارها نتيجة صحيحة.
3. يقبل الحالة `Announced` في حقلي الحالة، وتاريخ آخر بيع الكراسة المستقبلي، وعدم انتهاء الفرصة أو وجود تاريخ بداية مستقبلي. التاريخ المطلوب المفقود لا يُخمن. هذا تعريف تشغيلي محافظ لـ«سارية ومتاحة للمتقدم الجديد»؛ قد توجد فرصة ما زالت تقبل عروض من اشتروا الكراسة سابقاً ولا تدخل بهذا التعريف.
4. يطابق الوصف وتصنيف النشاط مع محطات الوقود/المحروقات/البنزين والفنادق والاستخدام الفندقي، **بما يشمل الشقق الفندقية**. يحاول استبعاد ذكر فندق أو محطة كمعلم مجاور. المطابقة النصية قابلة للتحسين وقد تخطئ في الأوصاف الغامضة؛ ليست ضمان تغطية كل فرصة معنونة بطريقة مختلفة. لا يفحص محتوى مرفقات PDF.
5. يرسل وصف الفرصة، رقمها، المدينة/الجهة عند توفرها، موعد بيع الكراسة بتوقيت الرياض ورابط صفحة التفاصيل. الرابط هو صفحة الفرصة وليس إحداثيات خرائط Google.
6. أول تشغيل `monitor` يرسل الموجود الساري، ثم يرسل غير المسجل فقط. يعالج حتى 100 رسالة في الدورة لتقييد الزمن، ثم يستكمل الباقي الساري في الدورة التالية. الفرص المنتهية قبل دورها لا تُرسل.
7. يحفظ التاريخ في `state/sent.json` بعد كل قبول إرسال ويحفظه Workflow في Git حتى عند فشل جزئي. الفرصة متعددة المواقع تُرسل مرة واحدة بالرقم والنوع، وتبقى كل التفاصيل في رابطها. التعديلات والتمديدات لن تعيد إرسال الرقم نفسه.

## الملفات

- `monitor.py`: الجمع، التصفية، الحفظ ودالتا إرسال Telegram وWhatsApp.
- `requirements.txt`: المكتبة المطلوبة.
- `.github/workflows/monitor.yml`: الجدولة والصلاحيات والمتغيرات.
- `state/sent.json`: تاريخ الإرسال، يبدأ فارغاً. لا تحذفه بعد بدء التشغيل.
- `tests/test_monitor.py`: اختبارات للحالات والمواعيد والتصنيف والدفعات والحفظ.

## 1. إنشاء المستودع ورفع الملفات

1. أنشئ حساباً في [GitHub](https://github.com)، ثم **New repository**.
2. سمّه `furas-monitor` واختر **Public** إذا أردت دقائق المشغلات القياسية المجانية. الكود وسجل معرفات الفرص سيظهران للعامة؛ لا تضع أي مفاتيح فيهما.
3. فك ضغط الحزمة. ارفع **محتويات** مجلد `furas-monitor` إلى جذر المستودع؛ يجب أن يظهر `monitor.py` في الجذر مباشرة.
4. من **Add file → Upload files** ارفع ملفات البرنامج ومجلدي `state` و`tests` وملف README وrequirements.
5. مجلد `.github` مخفي أحياناً. لضمان إضافته استخدم **Add file → Create new file** واكتب المسار `.github/workflows/monitor.yml`، ثم الصق محتوى الملف المرفق واحفظه على الفرع الافتراضي `main`.
6. افتح **Settings → Actions → General → Workflow permissions** واختر **Read and write permissions** ثم Save. ملف الجدولة يطلب `contents: write` لحفظ السجل. حماية الفرع أو سياسات المؤسسة التي تمنع كتابة Actions ستمنع الحفظ؛ استخدم مستودعاً مخصصاً يسمح بهذه الكتابة قبل إرسال أي فرص.
7. لا تُضف تشغيل `pull_request` إلى Workflow الذي يملك الأسرار.

## 2. إعداد تيليجرام المجاني — الخيار الافتراضي

1. افتح [BotFather](https://t.me/BotFather) الموثق في تيليجرام، وأرسل `/newbot`. اختر اسم البوت واسم المستخدم، واحتفظ بالتوكن سراً.
2. أنشئ مجموعة مخصصة وأضف البوت. اسمح له بإرسال الرسائل. أو أنشئ قناة وأضفه مشرفاً بصلاحية نشر الرسائل فقط.
3. للحصول على معرف مجموعة: أرسل `/start@اسم_البوت` داخل المجموعة. على جهازك شغّل مساعد الإعداد `python telegram_chat_id.py` بعد تثبيت المتطلبات؛ يطلب التوكن بإدخال مخفي ويعرض أسماء المحادثات ومعرفاتها. لا تضف التوكن إلى رابط متصفح أو سجل أوامر.
4. انسخ معرف المجموعة المقصودة (غالباً رقم سالب). إذا لم تظهر، تأكد من إرسال الأمر للبوت حديثاً ومن عدم استخدام خدمة أخرى تسحب تحديثاته. لقناة عامة يمكن استخدام `@channel_username` مباشرة.
5. في المستودع افتح **Settings → Secrets and variables → Actions → Secrets → New repository secret** وأضف:

| Secret | القيمة |
|---|---|
| `TELEGRAM_BOT_TOKEN` | توكن BotFather |
| `TELEGRAM_CHAT_ID` | معرف المجموعة أو القناة المقصودة |

6. تحت تبويب **Variables** أضف `NOTIFIER` بقيمة `telegram`، أو اتركه لأن ذلك هو الافتراضي.
7. لتكون قناة إعلانات لا دردشة: استخدم قناة Telegram، أو اجعل إرسال رسائل المجموعة للمشرفين فقط وأعطِ البوت صلاحية الإرسال. البرنامج نفسه يرسل إلى الوجهة المحددة فقط ولا يستقبل أوامر من المجموعة ولا يقرأ رسائلها أثناء المراقبة.

## 3. إعداد واتساب الرسمي — اختياري وله متطلبات وتكلفة

**لا تنفذ هذه الخطوات على أساس أنه يكفي حساب شخصي جديد.** إذا لم تكن مؤهلاً لـOBA فاستخدم تيليجرام أو قيّم مزوداً مدفوعاً يدعم احتياجك فعلياً.

1. أكمل إعداد WhatsApp Business Platform لدى Meta، وتحقق من أهلية OBA وGroups API وفق [دليل المجموعات](https://developers.facebook.com/documentation/business-messaging/whatsapp/groups) و[دليل البدء](https://developers.facebook.com/documentation/business-messaging/whatsapp/groups/get-started).
2. جهّز تطبيق Meta ورقم Cloud API وصلاحيات مراسلة WhatsApp وتوكن صالحاً للإنتاج؛ التوكن التجريبي المؤقت سينتهي. أنشئ مجموعة مؤهلة عبر الواجهة واحصل على **Group ID**؛ هذا ليس رقم الهاتف ولا رابط دعوة المجموعة العادية.
3. أنشئ قالباً نصياً باسم مثل `furas_opportunity_alert` ولغة `ar`، بمتغير واحد في الجسم، دون رأس أو أزرار تتطلب متغيرات. مثال جسم: `تنبيه فرص الاستثمار التي طلبتها: {{1}} للمزيد يرجى زيارة رابط الفرصة الوارد في التنبيه.` قدّم مثالاً واقعياً للمتغير وانتظر الموافقة. تصنيف القالب وتسعيره وموافقته تحددها Meta؛ لا تفترض أنه قالب مجاني.
4. اضبط إعدادات المجموعة بحيث يرسل حساب النشاط فقط وفق إمكانات الواجهة. هذا إعداد مستقل عن الكود؛ البرنامج لا يغيّر صلاحيات المشاركين.
5. أضف Secrets التالية بالطريقة السابقة:

| Secret | القيمة |
|---|---|
| `WA_ACCESS_TOKEN` | توكن مخول بالمراسلة |
| `WA_PHONE_NUMBER_ID` | معرف رقم المرسل في Cloud API |
| `WA_GROUP_ID` | معرف المجموعة التي أنشأتها Groups API |

6. أضف Variables التالية:

| Variable | القيمة |
|---|---|
| `NOTIFIER` | `whatsapp` |
| `WA_API_VERSION` | إصدار Graph API المدعوم لتطبيقك، بصيغة `vNN.0`؛ راجع لوحة Meta |
| `WA_TEMPLATE_NAME` | اسم القالب الموافق عليه بالضبط |
| `WA_TEMPLATE_LANGUAGE` | `ar` أو رمز لغة القالب الموافق عليه |

7. نفّذ وضع `test`. النجاح في السجل يعني قبول Meta لطلب الإرسال؛ تأكد بنفسك من ظهور الرسالة. الكود لا يستضيف Webhook لتتبع delivered/failed لاحقاً، فلا يعتبر قبول HTTP إثبات تسليم.

## 4. تجربة يدوية ثم التشغيل

1. افتح **Actions → Furas Monitor → Run workflow** على الفرع الافتراضي.
2. اختر `dry-run`: يجلب بيانات حقيقية ويعرض المرشحات دون أي إرسال ودون تعديل السجل. لا يحتاج مفاتيح الإرسال. راجع أن النتائج تلائم قصدك بالفنادق.
3. اختر `test`: يرسل رسالة اختبار واحدة فقط إلى القناة التي أعددتها؛ لا يسحب فرصاً ولا يسجل فرصاً كمُرسلة.
4. بعد رؤية الاختبار في المجموعة اختر `monitor`: يرسل أول دفعة من الفرص السارية، كل فرصة برسالة. اختبر بعناية إذا كانت واتساب لأن الرسائل قد تُحتسب بتكلفة.
5. بعد نجاح التشغيل، افتح `state/sent.json` في المستودع وتأكد من وصول commit حفظ السجل. أعد `monitor`؛ لا يفترض أن تتكرر الفرص المقبولة سابقاً.
6. الجدول `17 * * * *` يعمل عند الدقيقة 17 كل ساعة UTC، وهي الدقيقة 17 أيضاً كل ساعة بتوقيت السعودية. اختيرت الدقيقة بعيداً عن بداية الساعة لتقليل الزحام. لا يحتاج الجهاز الشخصي إلى البقاء مفتوحاً.
7. اشترك في إشعارات فشل GitHub Actions وراجع آخر تشغيل دوري. إذا توقفت الجدولة بسبب الخمول أعد تفعيلها من صفحة Workflow. غياب رسالة فرصة لا يثبت أن النظام يعمل.

يمكن ضبط Variable باسم `MAX_MESSAGES_PER_RUN` إلى رقم من 1 إلى 100. لا يُحذف تاريخ الوجهة القديمة عند تغيير قناة الإرسال؛ الوجهة الجديدة تحصل على الفرص السارية من البداية.

## التشغيل المحلي للاختبار فقط

استخدم Python 3.12:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m unittest discover -s tests -v
python monitor.py --mode dry-run
python telegram_chat_id.py
```

للإرسال المحلي مرّر القيم كمتغيرات بيئة من مدير أسرار أو بيئة آمنة. لا توجد مفاتيح في الكود ولا حاجة لملف `.env`؛ البرنامج لا يحمّل ذلك الملف تلقائياً. في GitHub تُحقن القيم تلقائياً من Secrets.

## حدود الدقة والاعتمادية والتعافي

- المصدر واجهة عامة تستخدمها الخريطة الرسمية، وليس عقد API مضموناً لهذا المشروع. تغيّر العناوين أو الحقول أو منع الوصول يحتاج تحديثاً. لا يتجاوز البرنامج تسجيل دخول أو حماية وصول.
- لا توجد معاملة ذرية تجمع إرسال الرسالة وحفظ Git. انقطاع العملية بعد الإرسال وقبل حفظ السجل في المستودع قد يسبب تكراراً في الدورة التالية. انتهاء مهلة الإرسال قد يعني قبول الرسالة دون وصول الرد. تفقد المجموعة قبل إعادة محاولة تشغيل فاشل؛ هذه النسخة لا تدعي ضمان exactly-once.
- إذا فشل حفظ Git: أوقف الجدولة مؤقتاً، وحمّل artifact باسم `notification-state-recovery` من التشغيل الفاشل، وأعد `state/sent.json` إلى المستودع، وتحقق من آخر رسائل المجموعة ثم أعد التفعيل. صلاحية artifact سبعة أيام ولا يُنشأ إلا عند فشل التشغيل.
- عند تلف/غياب السجل يتوقف البرنامج بدلاً من إعادة الإرسال الشامل. استرجعه من تاريخ Git. لا تعدّله أثناء تشغيل قائم.
- يقرأ البرنامج كل البيانات قبل البدء بالإرسال لتجنب إرسال نتائج مصدر جزئي. لا يعيد POST تلقائياً عند الشك، ويوقف الدورة عند أول فشل إرسال؛ الفرص غير المرسلة تبقى للدورة التالية إن ظلت سارية.
- السجل العام يحتوي معرفات الفرص ووقت قبول الإرسال وبصمة الوجهة، لا التوكن ولا رقم المجموعة الخام. من يملك صلاحية تعديل Workflow يستطيع تغيير سلوكه؛ اجعل الوصول الإداري للمستودع محدوداً.
- هذه الحزمة لم تُنشر في حساب GitHub ولم تُختبر برسالة حقيقية لعدم تزويدها بأسرار وجهة إرسال. إنشاء الحسابات والأهلية وإضافة الأسرار خطوات مطلوبة قبل التشغيل الفعلي.
